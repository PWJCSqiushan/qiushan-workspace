一个适合管理学习、项目、事务与生活的自托管工作台。用工作流组织事项，用协调数字决定执行顺序，用统计回顾实际进展。

> **当前公开版：工作流与时间看板。** 支持专用口令登录，也可配置 Cloudflare Access。尚未包含开放注册、用户名密码及邮件找回功能。默认口令模式下，各设备访问同一位使用者的数据；分享口令即分享工作台访问权限。
>
> 仓库提供脱敏源码与演示内容，不附带作者的真实卡片、生产数据库、登录凭据或云端资源配置。自行部署后使用自己的资源与网址。

<a id="quickstart"></a>
## 本地快速运行

准备 Git、Node.js 和 npm。建议使用 Node.js 24；项目已在 24.16 上验证。以下命令在仓库根目录执行。

```sh
git clone https://github.com/PWJCSqiushan/qiushan-workspace.git
cd qiushan-workspace
npm ci
npm run setup
npm run db:local
npm run dev -- --host 127.0.0.1
```

打开终端输出的地址。需要固定端口时使用：

```sh
npm run dev -- --host 127.0.0.1 --port 4326
```

- `setup` 仅在 `wrangler.jsonc` 不存在时复制示例，不覆盖已有配置。
- `db:local` 只应用本地 D1 迁移，不操作远程数据库。
- 开发服务在 loopback 地址上使用本地身份，无需生产口令。不要用此模式提供公网访问。
- 正式工作台初始为空；右上角切到“演示”体验示例。两者的卡片、编号、统计分开保存。
- 本地数据库位于 `.wrangler/`；草稿属于当前浏览器。换目录、端口或浏览器不等于迁移数据。

## 日常使用指南

### 第一次使用

1. 右上角选择“正式”或“演示”，建议先在演示空间熟悉操作。
2. 如果出现“连续编号尚未启用”，点击 **预览并启用编号规则**，核对变化后确认。
3. 点击 **新增事项**，填写名称、所属工作流和必要信息。
4. 选择本流优先级；需要明确执行顺序时填写协调数字。
5. 保存后检查顶部同步状态，确认已同步到云端。

### 五个视图

入口位于顶部指标下方的视图切换栏。

| 入口 | 用途 | 常用操作 |
| --- | --- | --- |
| 工作流总览 | 按九条流查看未结束事项 | 横向浏览、折叠工作流、编辑卡片 |
| 全局协调 | 跨流检查执行安排 | 查看紧急、本次先做、普通三个层级 |
| **统计总览** | 回顾一段时间的进展 | 选择日期、日周月粒度与工作流 |
| 历史 | 查看已结束事项 | 打开卡片，选择“恢复为待办” |
| 回收站 | 查看删除的事项 | 打开卡片，选择“从回收站恢复” |

搜索框可查找事项、地点或项目文本；今天、七天内、逾期、旗标按钮筛选看板内容。统计页使用自己的日期与工作流筛选。

### 读懂卡片与编辑器

| 位置 / 标识 | 含义与操作 |
| --- | --- |
| 标题与时间 | 点击卡片打开编辑器，填写日期、地点、预计用时、备注、检查清单 |
| 右侧“本流” | 在所属工作流内的重要程度 |
| 右侧“协调” | 协调字母与数字组合，如 `B 3`；数字决定执行先后 |
| 右上角旗标 | 点击关注 / 取消关注，只改变标记与背景，不改变排序 |
| 左下角对号 | 普通任务完成；每日例行切换当天打卡状态 |
| `EM` | 紧急事项，进入独立紧急区域 |
| 每日重复标识 | 每天独立记录打卡 |
| 本次先做 | 临时提前到普通事项之前，仅当天有效 |

编辑器可修改状态、优先级、日期、紧急、旗标和每日例行设置；“更多动作”中可复制或移入回收站。暂停中的任务需先恢复推进才能打卡。卡片保持统一尺寸，不使用项目大卡片或展开子任务布局。

<a id="categories"></a>
## 分类目录

分类是事项的可选补充标记。每条事项最多设置一个分类，分类目录按工作流独立维护；它只帮助识别，不改变协调数字、优先级、旗标、完成规则或统计口径。

- 在工作流标题旁点击分类图标，新增或编辑分类，设置全名、卡面简称和纯色背景。
- 全名最多 20 个 Unicode 字符；全名超过 3 个字符时填写 1—3 个字符的卡面简称。卡片使用简称，编辑器和目录保留全名。
- 停用分类后，旧卡片仍保留原引用并继续显示；新事项不能选择停用分类。将事项换到其他工作流时，原分类会清空。
- 分类目录和事项引用随 JSON、恢复前快照及云端备份保存。旧备份缺少分类目录时，恢复会保留当前目录；备份缺少历史时，界面提示历史不完整。

### 手机与平板

移动端可切换“紧凑列表”和“桌面总览”。Android 从浏览器菜单安装应用；iPhone / iPad 在 Safari 使用“分享 → 添加到主屏幕”。首次加载与登录需要联网。

<a id="ordering"></a>
## 协调排序与连续编号

### 先看层级，再看数字

```text
紧急事项 → 本次先做 → 普通事项
                 ↓ 每层内部
协调数字升序 → 协调字母 → 本流优先级 → 创建时间 → 卡片 ID
```

- **有数字排在无数字之前**；`0` 排在正整数之前。
- 字母沿用等级顺序，例如 `S、A+、A、A-、B+……`；未填写在明确等级之后，`NA` 最后。
- 数字相同或都未填写时，才继续比较协调字母和本流优先级。
- 每日例行、旗标和截止时间不额外打断排序；临期只作提示。
- 紧急与本次先做是显式置前例外，紧急事项仍保留独立区域。

**例子：** 同一层内，`B 2` 排在无数字的 `S` 之前，`A 4` 排在无数字的 `B` 之前。如果后者被设为紧急，则进入优先的紧急区域。

### 正整数由整个工作台共用

九条流的正整数统一保持 `1…N` 连续且唯一，不是每条流各自从 1 开始。正式与演示分别编号；紧急、本次先做事项也占用位置。

| 操作 | 结果 |
| --- | --- |
| 完成 `1` | 原 `2→1、3→2……` |
| 完成 `3` | `1、2` 不变，原 `4→3、5→4……` |
| 插入已占用的位置 | 当前卡片插入，后面的卡片顺延 |
| 移动已有编号 | 先释放旧位置，再插入新位置 |
| 输入超过队尾的数字 | 自动追加到队尾 |
| 删除、清空编号或改为 `0` | 释放旧正整数位置，后续卡片前移 |
| 撤销完成 / 恢复回收站卡片 | 插回保存的原位置；超过队尾则追加 |
| 完成 `0` | 其他编号不变，`0` 保留 |

`0` 允许重复，只能手动设置，不参与正整数补位。**留空不等于 0**：留空表示没有数字顺序，0 表示同层内最先。

完成后当前正整数会清除，原位置单独保存以供撤销。每日例行当天完成也释放正整数，次日不自动重新编号。协调字母选 `NA` 时，数字输入不可用。

<a id="analytics"></a>
## 统计总览与计算口径

点击顶部 **统计总览**，默认当前工作台、近 7 天、全部工作流。

- **时间范围：** 今天、近 7 / 30 / 90 天、自定义日期。
- **汇总粒度：** 日、周、月；统一北京时间，周一为一周起点。
- **工作流：** 全部或单条流。
- **图表：** 各流新增 / 完成柱状图、时间趋势折线图、完成占比环形图，以及数字明细。

| 指标 | 统计什么 |
| --- | --- |
| 新增卡片 | 所选时间内首次创建的卡片 |
| 总完成次数 | 普通任务完成与每日例行打卡之和 |
| 普通任务完成 | 所选时间内有效的普通任务完成事件 |
| 每日例行打卡 | 同日同卡最多一次的有效打卡 |

**计数规则：**

1. 撤销完成或重新打开任务，扣回原完成日期；再次完成计入新日期。
2. 编辑、移动工作流、恢复回收站和导入已有卡片，不制造新增事件。
3. 新增与完成分别归属于事件发生时所在的流，后续移动不改写归属。
4. 删除卡片保留已经发生的事件；撤销完成才撤回对应完成数。
5. 同步重试不重复计数；每日例行同日同卡最多一次。
6. 不用“完成数 ÷ 新增数”作为完成率，避免完成积压任务时产生误导。

页面显示数据截至时间、同步状态与历史覆盖说明。**历史不完整不等于没有完成过任务。** 旧数据只回填可核实的日期与流归属，不用最后修改时间猜测完成日期。离线或有待同步操作时，云端统计可能尚未包含本机修改。

<a id="sync"></a>
## 同步、草稿与冲突处理

```mermaid
flowchart LR
    A[设备上的编辑器] --> B[本机草稿与待同步操作]
    B -->|联网提交| C[Worker 认证与版本检查]
    C --> D[(D1 卡片与统计事件)]
    D -->|增量同步| A
    D -->|定时或手动备份| E[(KV 云端备份)]
```

- **草稿已保存 ≠ 云端已同步。** 草稿属于当前设备、浏览器，保存事项后还需观察同步状态。
- 离线修改进入待同步队列，恢复连接后重试；首次使用需在线初始化。
- 分类新增、改名、改色和停用也会进入待同步队列；事项引用分类前会先确保本机已经读取最新分类目录。
- 两台设备修改同一卡片时，可在冲突面板对照本机与云端，保存所选版本、另存新卡片或保留云端版本。
- 队列版本变化会保留操作并提示冲突。核对当前安排后，再选择“核对后按当前队列重新执行”。
- “数据与设置 → 本机未同步数据”可导出草稿与待同步操作，用于留存未提交内容；它与工作台 JSON 备份用途不同。
- 出现新版本提示时，先保存编辑并处理待同步操作，再点击“保存编辑后更新”。不要直接清空浏览器数据，以免丢失未提交内容。

<a id="backup"></a>
## 备份与恢复

入口：右上角 **数据与设置**。

| 功能 | 用途 |
| --- | --- |
| 导出当前工作台 | 下载当前空间 JSON，含卡片、分类目录、优先级、编号恢复位置、回收站与统计历史 |
| 立即创建云端备份 | 手动触发备份，成功后可下载留存 |
| 定时备份 | 示例配置每天 UTC 18:00，即北京时间次日 02:00 |
| 恢复前快照 | 导入前自动留存当前数据，可从列表中选择恢复 |
| 导出草稿与待同步操作 | 留存当前浏览器尚未提交的内容 |

容量达到保护阈值时可能停止新增云端备份，并显示提示；系统不会自动删除旧备份。请及时下载留存并检查容量。

### 恢复步骤

1. 确认右上角选中的是目标工作台。
2. 处理完待同步操作，另存当前工作台备份。
3. 点击“选择 JSON 备份”，检查卡片数量与来源。
4. 点击“确认恢复到当前工作台”，核对编号调整预览后确认。
5. 检查恢复后的卡片、编号与统计覆盖说明。

> **恢复会替换当前工作台，不是追加合并。** 恢复前会留快照，但仍建议下载独立备份。界面接受的 JSON 文件不超过 4 MB。旧备份缺少分类目录时会保留当前目录；备份缺少历史时，界面提示历史不完整。系统不凭空制造新增或完成事件。

## 部署到 Cloudflare

这是有数据库和服务端认证的应用，不能只上传静态文件到 GitHub Pages。需要自己的 Cloudflare 账户、Workers、D1 与 KV；资源额度以自己的套餐和 [官方说明](https://developers.cloudflare.com/workers/platform/pricing/) 为准。

### 1. 安装依赖并登录

```sh
npm ci
npm run setup
npx wrangler login
npx wrangler whoami
```

### 2. 创建资源并填写配置

仅首次部署创建；升级实例请沿用原资源。

```sh
npx wrangler d1 create personal-workspace
npx wrangler kv namespace create BACKUPS
```

将返回的信息填入本地 `wrangler.jsonc`，不要使用示例的全零 ID 远程部署。

| 配置 | 内容 |
| --- | --- |
| `name` | 自己的 Worker 名称 |
| `d1_databases[0].binding` | 保持 `DB` |
| `database_name` / `database_id` | 自己的 D1 名称 / ID |
| `migrations_dir` | 保持 `drizzle` |
| `kv_namespaces[0].binding` | 保持 `BACKUPS` |
| `kv_namespaces[0].id` | 自己的 KV 命名空间 ID |
| `vars.AUTH_MODE` | `passcode` |
| `vars.MIGRATION_ENABLED` | 字符串 `"false"` |
| `assets.run_worker_first` | `true` |
| `assets.html_handling` | `none` |

范本见 [wrangler.example.jsonc](wrangler.example.jsonc)。真实配置已加入 Git 忽略规则。

### 3. 初始化数据库

核对账户和绑定后执行；新库需要全部迁移，不要只执行最后一个 SQL：

```sh
npx wrangler d1 migrations apply DB --remote
```

### 4. 生成与配置口令

认证要求 **32 个随机字节生成的 43 位 base64url 口令**，不接受普通自选短密码。在自己的终端运行：

```sh
node -e "const c=require('node:crypto');const p=c.randomBytes(32).toString('base64url');console.log('Passcode: '+p);console.log('SHA-256: '+c.createHash('sha256').update(p).digest('hex'))"
```

将 `Passcode` 保存到密码管理器用于登录；把 `SHA-256` 的 64 位小写十六进制值输入下方命令的交互提示：

```sh
npx wrangler secret put LOGIN_SECRET_SHA256 --config wrangler.jsonc
```

首次创建时 CLI 可能询问是否创建该名称的 Worker，核对名称后继续。不要把口令或摘要写入源码、配置示例、Issue。更换口令时重新生成并更新此 secret，旧口令对应的会话会失效。配置方式见 [Cloudflare Secrets 文档](https://developers.cloudflare.com/workers/configuration/secrets/)。

### 5. 检查、构建并发布

```sh
npm test
npm run typecheck
npm run build
npx wrangler deploy --config dist/server/wrangler.json
```

使用构建生成的配置部署，打开终端返回的 HTTPS 地址，用原始口令登录。

建议在演示空间验证创建、改号、完成、统计和导出，再用第二台设备检查同步。**部署源码不会自动导入本机卡片**；需要迁移内容时，通过 JSON 备份恢复，并核对目标工作台。

<details>
<summary><strong>可选：Cloudflare Access 认证</strong></summary>

自行建立 Access 应用与访问策略，设置 `AUTH_MODE="access"`，并填写：

- `ACCESS_TEAM_DOMAIN`：完整的 `https://你的团队.cloudflareaccess.com`。
- `ACCESS_AUD`：对应 Access 应用的 Audience。
- `ALLOWED_EMAIL`：允许访问的邮箱。

确保访问路径经过 Access 并提供有效 JWT。该模式需额外身份与路由配置，不等于应用内开放注册。实现见 [lib/auth.ts](lib/auth.ts) 和 [lib/access-jwt.ts](lib/access-jwt.ts)。

<a id="upgrade"></a>
## 已有实例升级

**保留原 Worker 名称、D1 与 KV 绑定，才能继续使用原数据。**

1. 在各设备保存编辑、处理待同步操作，导出工作台 JSON 和未同步内容。
2. 创建并下载云端备份；数据库升级前，再导出完整 D1 SQL 到仓库之外的私有位置。
3. 保存本地源码修改，在干净分支更新代码；保留本地配置和 secret。
4. 安装依赖、检查并应用迁移，测试构建后发布。
5. 更新客户端；如果出现“预览并启用编号规则”，分别在正式 / 演示空间核对后启用。
6. 核对卡片数量、编号、统计与多设备同步，再恢复日常操作。

下方导出路径必须替换成自己的私有路径；Windows 用户可使用自己的盘符路径。

```sh
npx wrangler d1 export DB --remote --output="/absolute/private/path/workspace-before-upgrade.sql"
npm ci
npx wrangler d1 migrations list DB --remote
npx wrangler d1 migrations apply DB --remote
npm test
npm run typecheck
npm run build
npx wrangler deploy --config dist/server/wrangler.json
```

SQL 含私有数据与认证相关记录，不应上传公开仓库。连续编号迁移见 [0004_coordination_analytics.sql](drizzle/0004_coordination_analytics.sql)。

启用时先预览并留快照：保留所有 0；已有正整数按原数字、协调字母、本流优先级、创建时间与 ID 排序，再收拢为连续队列；未编号卡片保持未编号。旧客户端需要更新后重新确认新版队列操作。

代码发布与数据恢复是不同动作。需要回退时，先核对旧代码与当前数据库结构的兼容性，不要直接用旧备份覆盖正在变化的数据。

### 自定义与提交

工作流名称、说明和颜色见 [lib/domain.ts](lib/domain.ts)。已有数据通过流 ID 关联，改显示名称时保持 ID 稳定；改流数量需同时检查校验、布局和统计。

提交前检查 `git diff` 与 `git status`。公开内容不得包含真实卡片、数据库、备份、账户信息、口令、Cookie、私人截图或生产日志。忽略规则见 [.gitignore](.gitignore)；被忽略不等于已经脱敏，仍需核对提交内容。

本仓库没有连接生产账户的自动部署工作流；**推送 GitHub 不会自动发布网站。**

## 常见问题

<details>
<summary><strong>有数字的卡片为什么仍可能排在后面？</strong></summary>

先检查是否同属紧急、本次先做或普通层。置前例外先于数字；同层才按数字优先。若仍不符，检查是否保存并同步、是否启用连续编号，以及客户端是否更新。

</details>

<details>
<summary><strong>统计入口在哪里？为什么历史数量偏少？</strong></summary>

入口在顶部指标下方，与“工作流总览、全局协调、历史、回收站”并列。旧客户端需先保存草稿和待同步操作再更新。旧历史缺少可核实日期会标注不完整，不猜测补数；还应核对工作台、时间、工作流和同步状态。

</details>

<details>
<summary><strong>为什么删除卡片后完成数没有减少？</strong></summary>

删除保留已发生的历史事件；撤销完成才扣回原日期的完成数。导入旧卡片、恢复回收站也不算新建。

</details>

<details>
<summary><strong>部署后提示“登录尚未配置”怎么办？</strong></summary>

核对 AUTH_MODE、Worker 名称和该 Worker 的 LOGIN_SECRET_SHA256，摘要应为 64 位小写十六进制。网页登录输入原始 43 位口令，不是摘要。不要将线上认证改为 local 来解决。

</details>

<details>
<summary><strong>换设备后看不到卡片怎么办？</strong></summary>

确认同一线上地址、同一身份、同一正式 / 演示空间，并检查原设备是否同步成功。本地开发数据不会自动上传，草稿也不会自动跨设备出现。先导出留存，再排查，不要直接清空浏览器数据。

</details>

<details>
<summary><strong>本地启动报缺少表或 Node / SQLite 错误怎么办？</strong></summary>

确认执行过 npm ci、npm run setup、npm run db:local，使用建议的 Node 版本，并处于正确仓库目录。不要用操作生产数据库的方式修复本地迁移错误。

</details>

<details>
<summary><strong>能否多人注册并独立使用？</strong></summary>

当前公开版没有开放注册与邮件找回。默认口令模式适合一位使用者的多设备同步；需要独立数据的使用者可各自部署实例，共享口令不等于独立账户。

</details>

## 时间看板

在左上角切换到「时间」。提供60天、每格10分钟的时间点阵，日历与历史拖动、深浅主题，以及近1/7/30天时间占比、课程出勤和完整周对比。点格采用占时最多类别的单色；统计使用准确区间，而不是格子数量。未来计划不计入实际时间，课程须确认后才计入实际；出勤需独立标注。

从旧版升级需要先备份D1，再应用新增 `0005_time_board.sql`、`0006_time_plan_attendance.sql`。保留原工作流库与认证配置。不要把本机预览数据库或作者记录上传到你的部署。

支持文字、CSV、Excel与图片识别预览。OCR的日期和节次映射仍需人工核对，不能直接视为准确课表；Garmin本机同步器说明见 `scripts/garmin/README.md`。电脑关机时本机同步器不会运行。历史全快照容量优化和真实iPad Safari验收尚未完成。浏览器供应商许可见 `public/vendor/README.md`。
